# YoLink Local v0.6.1

## YS5708 / YS5707 local MQTT event capture

This is an instrumentation release intended to identify the exact Local Hub MQTT payload generated by the auxiliary physical buttons on YS5708-UC in-wall switches before Home Assistant device triggers are added.

### What changed

- Adds a bounded, RAM-only MQTT event capture for YS5708 and YS5707 devices.
- Also captures future/unknown models when a payload contains obvious button-like fields such as `keyMask`, `button`, or `pressType`.
- Captures the event name, normalized event data, raw MQTT payload, device model/type/name, and extracted candidate button fields.
- Stores at most 100 captured events and clears them on Home Assistant restart.
- Adds the capture to Home Assistant **Download Diagnostics** as `mqtt_event_capture`.
- Does not create Recorder entities, custom files, database rows, or background polling.
- Redacts obvious credential/token fields if they unexpectedly appear in a captured payload.

### Why this is a capture release

The official YoLink cloud integration supports YS5708 button 1/2 short- and long-press triggers, but we want to confirm that the Local Hub forwards the same fields before mapping them into native Home Assistant device automation triggers.

### Test sequence after install

1. Restart Home Assistant after installing v0.6.1.
2. On one YS5708-UC switch, press Button 1 normally.
3. Long-press Button 1.
4. Press Button 2 normally.
5. Long-press Button 2.
6. In Home Assistant, open **Settings → Devices & services → YoLink Local → Download diagnostics**.
7. Upload the resulting diagnostics file for analysis.

If the Local Hub exposes distinct button fields, the next release can map them to native HA device triggers without guessing at the protocol.
